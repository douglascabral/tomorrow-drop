# Transfer protocol — version 1

This document defines the versioned Tomorrow Drop protocol. The implementation is in `internal/protocol` and the limits in `internal/limits`. Any format change requires a version increment.

## 1. Overview

- Transport: TCP with TLS 1.3 (tasks 010–011). Identity authentication happens in the pairing and trust layer, not only through TLS.
- Discovery: UDP, `DISCOVER` and `ANNOUNCE` datagrams (task 017, not yet specified in detail).
- Control message encoding: UTF-8 JSON, inside length-prefixed frames.

## 2. Framing

Each control frame is:

```
+----------------------+---------------------------+
| size (uint32, BE)    | JSON payload (1..64 KiB)  |
+----------------------+---------------------------+
```

- The size is an unsigned 32-bit integer in big-endian.
- Size zero is invalid and results in `ErrMalformed`.
- A size above `limits.MaxControlFrameBytes` (64 KiB) results in `ErrLimitExceeded`. The rejection happens **before** the body is allocated.
- A truncated body or partial header results in `ErrMalformed`.
- A clean connection close, with no header byte received, results in `io.EOF`.

File and text data do not pass through this control framing. Its streaming format will be defined in tasks 028–031.

## 3. Version and negotiation

- Current version: `1` (`protocol.CurrentVersion`).
- Each side sends the list of versions it supports, in any order.
- Chosen version: the **highest** version present in both lists.
- No common version: the connection is closed with `ErrVersionMismatch`.
- No forced downgrade: the negotiated version is always one of the versions the local side supports.

Opening message (`HELLO`), sent by both sides after TLS:

```json
{"type":"HELLO","versions":[1]}
```

## 4. Session identifiers

- `SessionID` has 16 bytes generated by `crypto/rand`, shown as 32 hexadecimal characters.
- Each connection has a single `SessionID`, valid only for that connection.
- The identifier is **not** a credential. Authentication comes from the Ed25519 identity and TLS. Pairing confirmations must be bound to the `SessionID` and to both sides' public keys (task 013).

## 5. States

Security states of a peer (PRD §10), defined in `protocol.PeerState`:

| State | Label | Meaning |
|---|---|---|
| Discovered | `discovered` | Found over UDP, not authenticated |
| Connecting | `connecting` | Connection attempt in progress |
| Awaiting verification | `awaiting_verification` | Provisional TLS; only pairing is allowed |
| Trusted | `trusted` | Identity authenticated and persisted |
| Identity changed | `identity_changed` | Key differs from the stored one; blocked |
| Disconnected | `disconnected` | No active session |

An established TLS connection does **not** automatically lead to the `trusted` state.

## 6. Resource limits

Defined in `internal/limits`:

| Constant | Value | Use |
|---|---|---|
| `MaxControlFrameBytes` | 64 KiB | Control frame |
| `MaxDiscoveryDatagram` | 1 KiB | UDP discovery datagram |
| `MaxFileNameBytes` | 255 | File name |
| `MaxFilesPerOffer` | 1000 | Files per offer |
| `MaxTextBytes` | 1 MiB | Text or link |
| `MaxConcurrentTransfers` | 4 | Simultaneous transfers |
| `MaxDiscoveredDevices` | 256 | Ephemeral device list |

## 7. Timeouts

Defined in `internal/protocol/timeouts.go`:

| Constant | Value | Use |
|---|---|---|
| `HandshakeTimeout` | 10 s | TLS and version negotiation |
| `DecisionTimeout` | 60 s | Accept or decline of a receive request (PRD §13) |
| `IdleTimeout` | 30 s | Connection without traffic |
| `DiscoveryInterval` | 30 s | Periodic discovery queries (PRD §5.2) |

The values of `HandshakeTimeout`, `DecisionTimeout` and `IdleTimeout` are engineering decisions, not PRD requirements, and may be adjusted with a record in this section.

## 8. Errors

Protocol errors use the sentinels of `internal/apperr`: `ErrMalformed`, `ErrLimitExceeded`, `ErrTimeout`, `ErrCanceled`, `ErrUnauthorized`, `ErrIdentityChanged` and `ErrVersionMismatch`. Error messages sent to the peer do not include sensitive local data.
