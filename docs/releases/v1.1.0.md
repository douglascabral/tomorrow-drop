# Tomorrow Drop 1.1.0

**Transferred. Used. Done.** This version makes paired devices easier to reach, and adds the macOS graphical application for Intel Macs. It is compatible with 1.0.0: the protocol is still version 1, and devices paired before keep working.

## What is new

- **Paired devices on the home screen.** They have their own section, above the devices found, and stay there after a restart and when the device is on another network (another VLAN). Tapping one opens its actions (send, receive).
- **Online and offline.** Each paired device shows Online (green) or Offline (red). The app checks every 30 seconds while it is open, and when you press Refresh. The check is a plain TCP connection to the device's last address: nothing is sent, and it authorizes nothing.
- **Devices paired by IP stay listed** during the session, even when they never announce themselves.
- **iPhone and iPad:** Connect by IP has an IP field and a port field (47521 is filled in); the Paired devices section; a Receive action on the device screen; one line layout for every device.
- **macOS graphical application for Apple silicon and Intel.** `make package-macos` builds `TomorrowDrop-macos-arm64.app` and `TomorrowDrop-macos-amd64.app`.

## What is in this release

The same files as 1.0.0 (see [v1.0.0](v1.0.0.md) for the table and the install steps): the Linux `.deb`, the Windows `.exe`, the command-line programs for Linux, Windows and macOS (Apple silicon and Intel), and `SHA256SUMS`.

The macOS graphical application, the Android app and the iPhone/iPad app are built from source (`make package-macos`, `make install-android`, `make install-ios`). They are not published to any store, and the macOS bundles are not signed or notarized.

## Platforms tested

The automated suite passes (including the race detector) and the checks in `scripts/check.sh` pass. The macOS graphical application was run by the owner while this version was built. The iPhone and iPad screens of this version were only type-checked against the iPhone Simulator SDK: they have not been run on a device. The Intel macOS bundle was built, not run on Intel hardware.

## Known limits

- "Online" means that something accepts a connection at the device's last address. It does not prove it is the same device, and a device whose address changed shows Offline until it is connected to by IP once.
- The command-line program does not show online or offline.
- The limits of 1.0.0 remain (manual pairing, no resume of interrupted transfers, no code signing, the app must stay open on phones).
