# Tomorrow Drop 1.2.1

**Transferred. Used. Done.** This version puts the version in the name of every file of the release. It has everything that is in [1.2.0](v1.2.0.md) (unpairing an offline device on every system, a device listed once, the macOS disk images), and it is compatible with it: the protocol is still version 1, and devices paired before keep working. Nothing changes in how the applications behave.

## What is new

- **Every file has the version in its name**, so a downloaded file always says which version it is: `tdrop-1.2.1-linux-amd64`, `TomorrowDrop-1.2.1-linux-amd64.deb`, `TomorrowDrop-1.2.1-macos-arm64.dmg`. The release process refuses a tag that is not the version in the `VERSION` file, so a file cannot carry the wrong version.
- The command-line programs for macOS are `tdrop-1.2.1-macos-arm64` and `tdrop-1.2.1-macos-amd64` (they were `tdrop-darwin-*` in 1.0.0 and 1.1.0). Use the new names in scripts that download them.

## How the macOS application is signed

The release process signs the application and the disk image with a Developer ID, notarizes them with Apple and staples the ticket, when the signing credentials are set in the repository. **That path has not been run with a real certificate yet**: it is tested with fake signing tools, which prove the commands and the error handling, not Apple's acceptance. Without the credentials the application is signed ad hoc, and the build log says so. If macOS blocks the first open, Control-click the application and choose Open, or check the checksum and remove the quarantine flag with `xattr -dr com.apple.quarantine "Tomorrow Drop.app"`. The command-line programs for macOS are not signed with a Developer ID or notarized.

## Platforms tested

The automated suite passes (including the race detector) and the checks in `scripts/check.sh` pass. The macOS disk image was built and verified on an Apple silicon Mac, signed ad hoc. The Intel bundle was built, not run on Intel hardware. The iPhone and iPad screens were only type-checked against the iPhone Simulator SDK: they have not been run on a device. The Android app was not built for this version.
