# Tomorrow Drop 1.2.0

**Transferred. Used. Done.** This version lets you unpair a device that is offline on every system, lists a device only once, and publishes the macOS application as disk images. It is compatible with 1.1.0: the protocol is still version 1, and devices paired before keep working.

## What is new

- **Unpair an offline device, everywhere.** Tapping a paired device that is offline, or that has no known address, opens its screen without contacting it, and Unpair (and Rename) work from there. This was already so on iPhone and iPad; the desktop and Android applications now do the same. On iPhone and iPad a paired device with no address also opens its screen, with the send actions disabled until it has an address.
- **A device is listed once.** The same device paired again (a new key after a reinstall, often under another name) used to appear twice in the paired list. Only the latest pairing at an address is listed. The earlier one stays in the trust list, and can be removed in Settings or with `tdrop trust remove`.
- **macOS disk images.** The release includes `TomorrowDrop-1.2.0-macos-arm64.dmg` (Apple silicon) and `TomorrowDrop-1.2.0-macos-amd64.dmg` (Intel): open the image and drag Tomorrow Drop to Applications.
- **Every file has the version in its name**, for example `tdrop-1.2.0-linux-amd64` and `TomorrowDrop-1.2.0-linux-amd64.deb`, so a downloaded file always says which version it is.
- **The command-line programs for macOS are named `tdrop-1.2.0-macos-arm64` and `tdrop-1.2.0-macos-amd64`** (they were `tdrop-darwin-*` in 1.0.0 and 1.1.0). Use the new names in scripts that download them.

## What is in this release

The Linux `.deb`, the Windows `.exe`, the macOS disk images, the command-line programs for Linux, Windows and macOS (Apple silicon and Intel), and `SHA256SUMS`. See [v1.0.0](v1.0.0.md) for the install steps of the command-line programs.

The Android app and the iPhone/iPad app are built from source (`make install-android`, `make install-ios`). They are not published to any store.

## How the macOS application is signed

The release process signs the application and the disk image with a Developer ID, notarizes them with Apple and staples the ticket, when the signing credentials are set in the repository. **That path has not been run with a real certificate yet** (this project has no Apple Developer account at the time of this version): it is tested with fake signing tools, which prove the commands and the error handling, not Apple's acceptance. Without the credentials the release signs the application ad hoc, and its build log says so. If macOS blocks the first open, Control-click the application and choose Open, or check the checksum and remove the quarantine flag with `xattr -dr com.apple.quarantine "Tomorrow Drop.app"`. The command-line programs for macOS are not signed with a Developer ID or notarized.

## Platforms tested

The automated suite passes (including the race detector) and the checks in `scripts/check.sh` pass. The macOS disk image was built and verified on an Apple silicon Mac, signed ad hoc. The Intel bundle was built, not run on Intel hardware. The iPhone and iPad screens were only type-checked against the iPhone Simulator SDK: they have not been run on a device. The Android app was not built for this version.

## Known limits

- The limits of 1.1.0 remain: "Online" means that something accepts a connection at the last address, and the command-line program does not show it.
- Two pairings of the same device with no remembered address (made before the address was kept) cannot be told apart, so both are listed; unpair the old one from its screen.
- No code signing of the Linux and Windows packages, no resume of interrupted transfers, and the app must stay open on phones.
